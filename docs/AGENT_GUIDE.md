# Usage and agent guide

SVGDrawer is a Windows-local Python application, not a layout editor. Its browser
UI and CLI share `Gallery/` directly; neither requires a build nor a CDN.

## Discover and customize

Activate the project Conda environment with `conda activate ./.conda`, then run
`python svgdrawer.py`. Start the UI with `python start.py`; no shell launchers are used.

```powershell
python svgdrawer.py --list-all-flat --search chip --json
python svgdrawer.py --list-category --json
python svgdrawer.py --describe chip --json
python svgdrawer.py --list-parts chip --set pins=8 --json
python svgdrawer.py --create chip --set pins=8 --output exports/chip.svg --save-recipe exports/chip.asset.json --json
python svgdrawer.py --recipe examples/processor.asset.json --output exports/processor.png --json
```

Read `data.symbol.controls` and `data.common_controls` before selecting parameters.
Discover part IDs using the same parameters as the intended output; counts can
change available parts. Metadata discovery does not execute renderers.

Custom color arrays use fill, accent, stroke, highlight order. `default` resets
colors. Use `--params @FILE.json`, `--parts @FILE.json`, or `--color-sets @FILE.json`
for shell-independent JSON. Part overrides and output defaults survive saving variants.
PNG is always generated by Python/CairoSVG. The CLI first saves the SVG sidecar.
Use the project environment described in the README, not a global installation.

## Shared management

```powershell
python svgdrawer.py --add-category instruments --name Instruments --json
python svgdrawer.py --init-symbol sensor --category instruments --json
python svgdrawer.py --add-symbol sensor --script drafts/sensor.py --spec drafts/sensor.json --dry-run --json
python svgdrawer.py --add-symbol sensor --script drafts/sensor.py --spec drafts/sensor.json --json
python svgdrawer.py --import-svg drawing.svg --id drawing --name "Imported drawing" --json
python svgdrawer.py --save-symbol custom-chip --recipe exports/chip.asset.json --name "Custom chip" --style compact --json
python svgdrawer.py --update-symbol custom-chip --description "Compact processor" --tags chip,compact --json
python svgdrawer.py --move-symbol custom-chip drawing --category instruments --json
python svgdrawer.py --delete-symbol custom-chip drawing --json
python svgdrawer.py --list-trash --json
```

New writes support `--dry-run`. Trash and restore accept batches and validate the
whole batch before publication. Include all dependent symbols when deleting a
renderer owner. Restore original IDs/names; conflicts are errors, not overwrites.
For a nonempty category, explicitly choose `--contents uncategorized` or `trash`.
Use trash IDs from `--list-trash` with `--restore`, or `--purge ... --yes`.
Uncategorized cannot be deleted. Permanent removal never runs automatically.

The browser exposes the same actions through Manage Gallery, Add symbol and Save
symbol. Category deletion shows the affected count and requires a destination.
The browser periodically reloads metadata, including edits made by CLI processes.
There is no personal browser library or storage conversion; old storage is untouched.

## Backup and import

```powershell
python svgdrawer.py --backup-gallery --output Gallery.zip --json
python svgdrawer.py --import-gallery Gallery.zip --dry-run --json
python svgdrawer.py --import-gallery Gallery.zip --json
python svgdrawer.py --import-gallery Gallery.zip --force-sync --dry-run --json
python svgdrawer.py --import-gallery Gallery.zip --force-sync --yes --json
```

ZIPs contain the active `Gallery/` directly, excluding trash, history, locks and
caches. Default import adds nonconflicting symbols and missing categories; local
settings, palettes and helpers remain unchanged. Different renderer/helper code
is a conflict, not silently reused. Full sync replaces active content and saves
it as a trash snapshot. Restore snapshots with `--restore TRASH_ID --dry-run`, then
`--restore TRASH_ID --yes`; the displaced Gallery becomes another snapshot.

**Python sources are executable trusted code.** Registration/import validation
executes renderers in a subprocess, not a security sandbox. Review sources first.

## Automation

Commands are noninteractive. Use schema-2 `--json` and check the exit code. Success
is one stdout envelope; failure is one stderr envelope. Avoid `--debug` when parsing.
`--force` is explicit replacement permission; it is not interchangeable with
`--force-sync --yes`. Respect active `.write.lock` files; retry instead of removing them.
Read [CLI reference](CLI_REFERENCE.md), [source conventions](EXTENDING.md), and
[architecture](ARCHITECTURE.md). Run the tester checks in [TESTING.md](TESTING.md).

## Naming related symbols (for AI agents)

Before adding a symbol, search the catalog by concept, aliases, geometry and function,
then inspect related definitions and controls. Do not decide similarity or identity
from `style` alone. Consider the depicted object, purpose, topology, perspective,
shape, fixed details, and which details users can actually customize.

Use consistent, descriptive display names. For example, avoid an inconsistent set
like "CPU", "CPU 3D", "CPU 6pin". Prefer names such as "Square processor with adjustable
pin rows", "Perspective processor package", and "Rectangular processor with six fixed
contacts" when those distinctions are true of the actual artwork. Do not label a
configurable pin family by its current default count; a fixed-count name is appropriate
for a genuinely fixed source. Style (e.g. rounded-outline) supplements these distinctions.

**Agents may rename existing display names while adding related symbols** when that
makes the family clearer and more precise. Use `--update-symbol ID --name "..."`; keep
stable IDs, renderer references, recipes, parameters and part IDs unchanged. Retain a
useful previous name or common term in tags for discovery, check global name uniqueness,
and report the renames. Do not add redundant copies merely to change a label or style.
The catalog remains small; use names, descriptions and tags rather than a new taxonomy.

For third-party SVGs, prefer verified upstream sources from collections listed on
FreeIcons. Keep collection/source URL and license information in symbol configuration,
the upstream notice in `LICENSE.txt`, and attribution/license text inside the SVG `desc`.
The shared PNG exporter preserves that text in PNG Description metadata. Do not strip
notices when saving variants or redistributing artwork. See [Third-party artwork](THIRD_PARTY.md).
